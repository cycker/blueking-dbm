第 14 章 · DBHA 与故障自愈

蓝鲸 DBM 中 MongoDB 的接入层高可用（DBHA）与整机级故障自愈是两条不同链路：前者在 mongos 不可用时从 DNS/CLB 摘除故障节点；后者在 DBHA 或人工确认后，由平台自动创建 MONGODB_AUTOFIX 工单申请新机并走替换 Flow。本章说明适用范围、流程与排障入口。

14.1概念区分（必读）

能力作用对象触发方典型结果
MongoDB 副本集选举分片内 shard / 副本集 mongodMongoDB 内核Primary 在 m1/m2 间切换；不由 DBHA 服务驱动
DBHA（mongos）分片集群接入层 mongosdbha 探测失败 → 切换队列从 DNS / CLB 摘掉故障 mongos IP
故障自愈（Autofix）故障 整机（mongos / mongod 所在机器）周期任务读 HADB 切换队列 → 建单MONGODB_AUTOFIX → 资源池新机 + 替换 Flow
💡
📌 副本集业务高可用：依赖 ≥3 成员 + m1/m2 priority=1 + backup priority=0，见 第 2 章。 分片集群业务入口高可用：依赖 ≥2 个 mongos + 集群入口域名/CLB；DBHA 只负责「坏 mongos 不再被解析到」，不替代 shard 内 mongod 选主。

14.2DBHA：mongos 探测与切换

14.2.1 适用范围

项目说明
集群类型仅 MongoShardedCluster
实例类型仅 mongos（machine_type=mongos）
不覆盖副本集 MongoReplicaSet、config server、shard 上的 mongod（存储层切换由 MongoDB 副本集机制处理）

实现代码位于：

dbm-services/common/dbha/ha-module/dbmodule/mongodb/
├── mongos_detect.go    # Agent 探测
├── mongos_switch.go  # GDM 执行切换
└── mongos_callback.go

14.2.2 探测逻辑（Agent）

对每个 mongos（同一主机只探测最小端口实例）：

  1. 使用 MongoDB Go Driver 连接 mongodb://<ip>:<port>，执行 buildInfo（超时见 DBConf.MongoDB.Timeout，默认约数秒级）。
  2. 若连接/命令失败 → 再 SSH 探测（touch 标记文件；区分认证失败与主机不可达）。
  3. 状态上报 GDM；失败实例进入切换流水线。

14.2.3 切换逻辑（GDM）

切换步骤（见 mongos_switch.go 注释）概要：

步骤动作
CheckSwitch校验角色为 mongos；若绑定了 DNS，要求该域名下 至少还有 1 个其他 IP（len(BindIps) > 1），避免把入口摘空
DoSwitchKickOffDns：从域名解析中删除本机；KickOffClb：从 CLB 后端摘除本机
UpdateMetaInfoMongoDB mongos 切换 不回写 CMDB 主从对调（与 MySQL 整机切换不同）

切换成功/失败会向蓝鲸监控上报自定义事件（与 §13.9 策略对应）：

事件名告警级别含义
dbha_mongos_switch_succ3（提醒）已从入口摘除故障 mongos
dbha_mongos_switch_err1（严重）摘除 DNS/CLB 失败

14.2.4 运维注意

  • mongos 至少 2 台：与拓扑规范一致；仅 1 台时 DBHA 可能因「DNS 只剩 1 IP」而 拒绝切换。
  • CLB / DNS 工单：接入层需先按平台规范绑定；无 DNS/CLB 时对应 KickOff* 为 no-op，切换效果依赖客户端连接方式。
  • 切换 ≠ 换机：DBHA 只做流量摘除；若要新 mongos 实例，需走 自愈 或 扩容/替换 工单。

14.3故障自愈（MONGODB_AUTOFIX）

14.3.1 与 Redis 自愈共用框架

MongoDB 自愈复用 Redis 侧的自愈表与周期任务（历史命名保留）：

组件路径 / 说明
周期任务dbm-ui/backend/db_periodic_task/local_tasks/redis_autofix.py
切换队列监听watch_dbha_switch（每分钟）
建单start_autofix_flow → generate_autofix_ticket
Mongo 建单封装dbm-ui/backend/db_services/mongodb/autofix/mongodb_autofix_ticket.py
Flow 入口flow/engine/bamboo/scene/mongodb/mongodb_autofix.py · MongoAutofixFlow
状态表RedisAutofixCore / RedisAutofixCtl

总开关：RedisAutofixCtl 中 ctl_name=enable，值为 off 时所有 DBHA 后续自愈不推进。

14.3.2 触发链路

flowchart LR
  A[dbha 切换队列 HADB] --> B[watch_dbha_switch]
  B --> C[按集群聚合故障机]
  C --> D[start_autofix_flow]
  D --> E{机器类型?}
  E -->|mongos / mongod| F[mongo_create_ticket]
  F --> G[MONGODB_AUTOFIX 工单]
  G --> H[MongoAutofixFlow]
  1. watcher_get_by_hosts：自 HADB query_switch_queue_by_uid 增量拉取切换记录，按 故障 IP 聚合。
  2. check_and_process：过滤忽略列表、多集群共用 IP 等异常后，写入 RedisAutofixCore。
  3. generate_autofix_ticket：识别 MachineType.MONGOS 或 mongod 角色 → 调用 mongo_create_ticket。
  4. 以业务 MongoDB DBA 为创建人自动提交 MONGODB_AUTOFIX，并企业微信通知。

工单常量见 第 4 章 §4.7。

14.3.3 自愈 Flow 分支

集群类型Flow行为概要
MongoReplicaSetMongoReplaceFlow.multi_host_replace_flow对故障机上的 mongod 整机替换（资源池申请 → 安装 → 元数据/域名）
MongoShardedClusterMongoClusterAutofixFlow.cluster_autofix_flow分 mongos、mongo_config、shard mongod 子流程（mongos_autofix / shard_autofix 等）

分片集群 mongos 自愈典型步骤（cluster_monogs_autofix.py）：新机安装 mongos + dbmon → 加密码/域名 → 挂 CLB → 下架旧实例等（与手工「扩容 mongos + 下架」类似，由 Flow 串行）。

mongos 资源池选址：若健康 mongos 超过半数在同一园区，新机 排除 该园区，避免故障域集中（mongos_get_resource_spec）。

14.3.4 自愈状态（AutofixStatus）

状态含义
initautofix / start / initticket排队、准备建单
watchflow / running工单 Flow 执行中
reuse_host尝试复用机器（Redis 路径为主）
success / fail终态

可在 DBM 工单列表按类型 MONGODB_AUTOFIX 跟踪；失败时查看 RedisAutofixCore.status_version 与工单 Job 日志。

14.5排障速查

现象优先检查
收到 dbha_mongos_switch_errmongos 是否仍挂在 DNS/CLB；域名下是否只剩 1 IP；CLB API / 权限
收到 dbha_mongos_switch_succ 但业务仍连旧 IP客户端 DNS 缓存、长连接未重建；是否直连 IP 而非集群域名
故障 mongos 未自愈RedisAutofixCtl.enable 是否为 off；IP 是否在忽略列表；HADB 队列是否有记录
自愈单卡住资源池规格/园区约束；MONGODB_AUTOFIX 工单 Flow 节点失败日志
副本集 Primary 不可用rs.status()、选举、网络；走 实例重启/整机替换 工单，而非 DBHA
分片 shard 主节点切换shard 副本集选举；DBHA 不会 切换 mongod
