第 3 章 · 首次部署 MongoDB

面向从未部署过 MongoDB 的同学，介绍如何在蓝鲸 DBM 中通过标准化工单驱动安装与元数据注册。

💡
本章不等同于在裸机上手工 mongod + 改配置。

3.1范围说明 边界

  • 本章描述 在 DBM 内首次创建 MongoDB 集群 的路径，通过工单驱动安装。
  • 不等同于在裸机执行 mongod 与手工改配置。
  • 若脱离 DBM，请参考 MongoDB 官方「Install」与生产 checklist。

类别必备项

3.3选型：副本集 vs 分片集群 决策

维度副本集分片集群
适用数据量 / 写入在「多副本」内可满足需 多分片 线性扩展
组件mongod 副本mongos + config + 多个 shard（每片多为副本集）
运维复杂度相对较低更高（路由、均衡、分片键与扩容策略）
💡
✅ 建议：不确定时优先 副本集；确需水平分片再选 分片集群。

3.6DBM 配置模板与参数 dbconfig

部署时 不会 让你在工单里手写完整 mongod.conf。平台从 dbconfig 配置模板 读取默认值与校验范围，再结合 主机规格、工单里的 oplog_percent 等，算出 dbactuator 的 dbConfig，生成实例上的 YAML/INI 并写入配置库。

3.6.1 配置从哪里来

提单（spec_id、oplog_percent、db_version …）
        ↓
calculate_cluster / mongodb_dataclass（按内存、磁盘算 cache / oplog）
        ↓
get_mongodb_conf() → 读取 dbconfig 模板 Mongodb-{主版本}
        ↓
mongod_install 原子任务 → 本机 mongod.conf + 目录布局
        ↓
save_conf() → 配置持久化到 dbconfig（集群级，namespace=集群类型）
层级说明运维入口（以当前 DBM 为准）
plat / app / cluster模板支持 plat,app,cluster 三级覆盖；版本化在 cluster 级（level_versioned: cluster）平台 配置管理 / 集群 配置项
部署工单只暴露部分业务参数（如 oplog_percent、spec_id）；其余走模板默认 + 自动计算部署单据表单
实例文件安装完成后本机 mongod.conf（3.0+ 为 YAML）SSH 到节点查看（排障用）

源码索引：

说明路径
副本集 / 分片 模板注册dbm-ui/backend/components/dbconfig/migrations/MongoReplicaSet/ · MongoShardedCluster/
dbconf 参数定义（按大版本）.../dbconf/Mongodb-3.json · Mongodb-4.json · Mongodb-6.json · Mongodb-7.json

部署时拉模板flow/utils/mongodb/mongodb_dataclass.py → get_mongodb_conf()

3.6.2 模板文件与集群类型

集群类型 namespace配置类型 conf_type配置文件 conf_file适用 MongoDB 大版本
MongoReplicaSetdbconfMongodb-3 / 4 / 6 / 7主版本 3 / 4 / 6 / 7（与介质 db_version 对齐）

📌 选择版本时：平台取 db_version 的 主版本号（如 4.4.25 → 模板 Mongodb-4）。未在 migrations 中登记的版本组合，部署前需在 dbconfig 侧确认是否已导入对应模板。

3.6.3 副本集 dbconf 参数（模板 + 含义）

下表来自 MongoReplicaSet/dbconf/Mongodb-4.json（6/7 等同结构；默认值各版本文件可能略有差异）。允许范围以环境内 dbconfig 为准。

参数名模板默认（示例）允许范围（示例）是否需重启写入 mongod.conf（3.0+）说明
cacheSizeGB1010～80是storage.wiredTiger.engineConfig.cacheSizeGBWiredTiger 缓存；部署时按内存重算，见 §3.6.5
oplogSizeMB1024010240～81920是replication.oplogSizeMB副本集 oplog 上限；部署时按磁盘与 oplog_percent 重算
slowOpThresholdMs200100～2000是operationProfiling.slowOpThresholdMs超过阈值记慢查询；见 第 9 章 · 日志
destinationfile仅 file是systemLog.destination日志输出到文件
key_file空—是security.keyFile副本集认证；安装时由平台生成路径与内容，非手填

部署工单直接相关的只有 oplog_percent（整数，表示磁盘容量用于 oplog 的 百分比）。spec_id 决定主机内存/磁盘，间接决定算出来的 cacheSizeGB / oplogSizeMB。

3.6.4 分片集群额外 dbconf 参数

在副本集参数基础上，分片模板增加 config server 专用项（MongoShardedCluster/dbconf/Mongodb-4.json）：

参数名作用对应角色
config_cacheSizeGBconfigsvr WT 缓存mongo_config
config_oplogSizeMBconfigsvr oplogmongo_config
cacheSizeGB / oplogSizeMB各 shard 副本集成员mongodb（shard 上的 mongod）

mongos 安装使用精简 dbConfig（通常仅 slowOpThresholdMs、destination 等），无 oplog 段。

3.6.5 自动计算公式（部署流水线）

工单提交后，calculate_cluster.replicase_calc / 分片等价逻辑会 覆盖 模板里的 cacheSizeGB、oplogSizeMB：

输出参数计算公式（概念）常量来源
cacheSizeGBint(主机内存 MB × 0.65 / 单机部署实例数 / 1024)，最小 1MongoDBTotalCache.Cache_Percent = 0.65
oplogSizeMBint(数据盘 GB × 1024 × (oplog_percent ÷ 100) / 单机部署实例数)工单字段 oplog_percent（如填 10 表示 10%）

说明：

  • 单机部署实例数：node_replica_count（同一台机器上跑几个 mongod 端口）。
  • 数据盘：优先 /data1，否则 /data（见 calculate_cluster.py）。
  • 模板中的 value_default（如 oplog 10240MB）多用于 配置中心校验/展示；新集群首次安装以计算值为准。

3.6.6 安装 payload 与落盘示例

mongod_install 收到的 dbConfig 片段（与 dbm-services/mongodb/db-tools/dbactuator/example/mongod_install.example.md 一致）：

{
  "dbConfig": {
    "slowOpThresholdMs": 200,
    "cacheSizeGB": 12,
    "oplogSizeMB": 51200,
    "destination": "file"
  },
  "clusterRole": ""
}
  • 副本集：clusterRole 留空。
  • 分片 shard：clusterRole: "shardsvr"。
  • config server：clusterRole: "configsvr"。

生成的 3.0+ YAML 核心字段（逻辑映射）：

storage:
  dbPath: /data/mongodb/{port}      # 由安装路径规则生成，非 dbconf 表字段
  engine: wiredTiger
  wiredTiger:
    engineConfig:
      cacheSizeGB: 12                 # ← dbConfig.cacheSizeGB
replication:
  replSetName: {set_id}
  oplogSizeMB: 51200                  # ← dbConfig.oplogSizeMB
systemLog:
  destination: file                   # ← dbConfig.destination
  logAppend: true
  path: {BackupDir}/mongolog/{port}/mongo.log
operationProfiling:
  slowOpThresholdMs: 200              # ← dbConfig.slowOpThresholdMs
net:
  port: {port}
  bindIp: 127.0.0.1,{本机IP}

日志路径、数据目录、keyFile 等由 dbactuator 安装逻辑写死规则，不在 dbconf JSON 模板里逐项暴露。

3.6.8 部署后修改配置

  1. 推荐：DBM 集群 配置管理 中修改 dbconf 项 → 走平台「配置变更」类工单（若有）→ 滚动生效；need_restart: 1 的项需重启实例。
  2. 紧急排障：登录节点改 mongod.conf 仅作临时手段，需记录并与平台配置对齐，避免下次安装/替换被覆盖。
  3. 关联阅读：日志与慢查询阈值 → 第 9 章；拓扑与 backup 节点 → 第 2 章。

3.7提交后跟进 排障

  1. 查看流水线节点：打开 工单中心，确认所有节点状态为成功。
  2. 查看脚本日志：失败时进入单据详情，查看 标准运维 / Job 平台 返回的脚本日志（路径与 MySQL/Redis 一致）。
  3. 常见失败方向：资源规格不足、亲和与可用区冲突、端口占用、安装包缺失或未启用 …… 具体以校验错误信息为准。
